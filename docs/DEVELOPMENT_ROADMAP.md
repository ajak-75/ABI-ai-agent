# 개발 로드맵

각 단계는 "이전 단계가 실제 기기에서 검증됐다"는 전제로만 시작합니다. 예산은 0원을 기본선으로 두고, 유료가 필요해지는 지점에서 반드시 먼저 보고합니다.

- [x] 독립 프로젝트 + GitHub 저장소
- [x] 4탭 UI(대화·기억·작업·설정)와 채팅 인터페이스
- [x] SQLite 스키마·마이그레이션·CRUD, 재실행 후 대화 유지
- [x] 세션 목록/삭제, 사용자 기억 CRUD
- [x] 승인 정책·승인/거절 기록·감사 로그
- [x] SecureStore 키 보관(마스킹)
- [x] 하이브리드 라우터 골격(local/cloud_free/auto)
- [x] Development Build 구성(expo-dev-client + eas.json APK)
- [x] 타입 검사·Expo 설정 검증
- [ ] 실기기 APK 설치·실행 (빌드 환경 확보 후)

## PHASE 2 — 로컬 엔진 연결

목표: 네트워크 없이 실제 답변이 나온다.

1. 후보 비교(APK 크기·메모리·한국어 품질): llama.cpp 계열 RN 바인딩 vs ONNX Runtime Mobile vs 기기 내 ML Kit 계열
2. `AiEngine` 구현체 추가 → `hybridRouter.engines.local` 교체
3. 모델 파일 배포 방식 결정(앱 번들 vs 최초 실행 시 다운로드 → 후자는 네트워크 정책 변경 필요)
4. 토큰 스트리밍 UI(말풍선 점진 표시), 취소 버튼
5. 실기기 측정: 첫 토큰 지연, 초당 토큰, 배터리·발열
6. 기준 미달이면 자동 모드를 무료 클라우드 우선으로 조정

## PHASE 3 — 무료 클라우드 API + 도구 실행

1. 무료 티어 API 1곳 선정(요금·호출 한도·약관 확인 후)
2. `AiEngine` 구현 + 키는 `readApiKey`로만 읽기, 실패 시 로컬 폴백
3. 사용량 카운터(로컬 기록)와 한도 초과 시 안내
4. 도구 1~2개 등록(예: 기기 캘린더 읽기, 알림 예약) + 승인 흐름 연결
5. 승인 대기 → 승인 후 실행 → 결과 저장 → 감사 로그까지 실기기 검증

## PHASE 4 — 개인화와 편의

- 기억을 대화 컨텍스트에 자동 주입(현재는 저장만)
- 대화 검색, 메시지 복사·공유
- 다크 모드
- 백업/복원(로컬 파일 내보내기, 암호화 여부 검토)
- 접근성(글자 크기, 스크린리더 라벨) 점검

## PHASE 5 — 배포 판단

- 개인 설치(APK 직접) 유지 vs Google Play 등록($25 1회, 선택)
- 서명 키 보관 방식 결정(EAS 관리형 vs 자체 keystore)
- 개인정보 처리방침 문구 정리(로컬 전용임을 명시)

## 리스크와 대응

| 리스크 | 대응 |
| --- | --- |
| 로컬 모델이 폰에서 너무 느림 | 자동 모드 기본값을 클라우드로, 로컬은 명시 선택 시만 |
| 무료 API 한도 소진 | 사용량 로컬 카운터 + 한도 임박 안내 + 로컬 폴백 |
| APK 크기 급증(모델 포함) | 모델 분리 다운로드(다운로드 시 사용자 동의) |
| 승인 없는 외부 행동 | `DEFAULT_POLICY`에서 medium 이상 무조건 승인 유지 |
| 데이터 손실 | 설정의 백업/복원(4단계) 전까지는 삭제 확인 다이얼로그 유지 |
